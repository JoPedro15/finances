# Development Guidelines

This file contains a set of rules to be followed during the development of this project.

## Language and Style
1.  **Language**: All code, including comments, variable names, and documentation, must be written in English.
2.  **Code Style**: Preserve the existing code style in the project.
3.  **Readability**: Prefer explicit and readable code over clever or compact solutions.

## Documentation
1.  **Function Documentation**: All new functions must include a docstring explaining their purpose, arguments, and what they return.
2.  **Update Documentation**: When changing a function, its documentation (docstring) must be validated and updated before applying any other modification.

## Code Conventions
1.  **Type Annotations**: Every newly created variable must include an explicit type annotation.
2.  **No Public API Changes**: Do not change public APIs (e.g., function signatures) without prior confirmation.

## Working Approach
1.  **Read Before Editing**: Before editing a file, always read its content to understand the context.
